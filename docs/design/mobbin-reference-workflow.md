# Mobbin Reference Workflow

Mobbin is a visual-reference system, not a design authority. References inform structure, hierarchy, grouping, and interaction conventions. Kaoshi/Hermes tokens, components, accessibility rules, and product requirements remain authoritative.

## Workflow

1. Define the page problem before searching.
2. Classify the page type and primary user task.
3. Select needed page and component patterns.
4. Search Mobbin by specific pattern terms, not broad product labels.
5. Compare at least three references when possible.
6. Extract what is structurally useful.
7. Document what must not be copied.
8. Adapt the proposal to Kaoshi/Hermes design constraints.

| Row triage | review queue, bulk action table, moderation queue | table |

## Rules

- Do not copy a complete Mobbin screen.
- Do not import another product's brand, palette, typography, or spacing identity.
- Do not use Mobbin to justify inaccessible controls.
- Do not skip product requirements because a reference looks better.
- References must be cited in proposals by the pattern they support.
