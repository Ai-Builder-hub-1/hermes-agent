# Dashboard Quality Scorecard

Dashboard quality is judged by operating usefulness, not by component presence
alone.

Score each reviewed surface across these dimensions:

| Area | Requirement |
|---|---|
| Shell | One app shell, Tier 3 operational sidebar, compact command header. |
| Hierarchy | The primary question, current state, and next action are visible without hunting. |
| Density | Tables, charts, metrics, and feeds are dense enough for repeated operator use. |
| States | Loading, empty, error, stale, partial, and permission-restricted states are defined. |
| Data | Freshness, owner, confidence, and action-needed signals are visible. |
| Accessibility | Keyboard path, focus visibility, names, contrast, and reduced motion are covered. |
| Responsiveness | Desktop expanded, desktop collapsed, and mobile behavior are proven. |
| Visual Taste | Mobbin references inform structure, but Hermes tokens and components own the final UI. |

Automated checks are advisory unless they fail hard gates. Human review remains
required for premium taste and decision readiness.
