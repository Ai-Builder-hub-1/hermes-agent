2. page-contract: Page declares purpose, target user, data contracts, required states, validation, and proof expectations.
3. data-binding: Page is wired to live API, warehouse, or generated evidence data with source and freshness context.
4. state-coverage: Page renders normal, loading, empty, error, stale, degraded, critical, permission-limited, and mobile states.
5. observability: Page shows worker, collector, runner, sync, storage, alert, or deployment status where relevant.
6. drill-down: Aggregate signals link to project, source, worker, job, table, event, alert, or evidence-level detail.
7. cross-project-standard: Infrastructure telemetry uses shared fleet schemas and can be compared across projects.
8. command-control: Operational commands are permissioned, audited, confirmed, and tied to rollback or recovery evidence.
9. alerting-escalation: Warnings and critical alerts have thresholds, dedupe, ownership, dashboard links, and resolution tracking.
10. warehouse-storage: Collection, database growth, external mirror, retention, pruning, backup, restore, and orphan evidence are visible.
11. component-maturity: Page uses dashboard-kit or approved domain components with no static placeholder surface.
12. ux-visual-maturity: Layout, density, filters, responsive behavior, severity language, and empty states are production-quality.
13. testing-proof: Build, route smoke, contract, state, permission, command, screenshot, and production smoke proof exists.
14. governance-ledger: Route status, blockers, evidence, and next maturity action are recorded in this ledger.
15. production-readiness: Route is data-bound, tested, deployed, observable, actionable, and regression-protected.
