# Nous / Hermes Page Map

This guide maps the current pages in the Nous Hermes app from the checked-in routes and API wiring. It is meant as an operator reference: what each page is for, why it exists, what you can do from it, and what data you can expect to find there.

Sources used:

- `web/src/dashboard-route-registry.tsx`
- `web/src/dashboard-page-metadata.ts`
- `web/src/lib/api.ts`
- `apps/desktop/src/app/routes.ts`

## Fast Mental Model

Use the app in four layers:

1. **Daily work layer**: Chat, Sessions, Files, Artifacts, Skills, Models, Cron, Logs.
2. **Connection layer**: Keys, Config, Providers, MCP, Plugins, Channels, Webhooks, Pairing, Profiles.
3. **Command layer**: Central Command, Hermes OS, Trading Command Center, Head Trader, Executive, Business OS, Incident, Deployment, Cost, Learning, Evaluation.
4. **Governance and rollout layer**: the many generated dashboard pages. These exist to show readiness, data contracts, required states, ownership, evidence, and rollout progress across the operating system.

If you only have 15 minutes, check:

- `/sessions` for what has been worked on.
- `/chat` for doing new work.
- `/models`, `/env`, and `/config` for whether the system can think/run correctly.
- `/skills`, `/plugins`, and `/mcp` for capability expansion.
- `/cron` for scheduled automations.
- `/central-command`, `/trading-intelligence`, `/head-trader`, and `/fleet-maturity-review` for command-level status.

## How To Use This Well

- Start with **Sessions** when you are trying to remember what happened.
- Start with **Chat** when you want to do something new.
- Start with **Skills / Plugins / MCP** when you feel the agent is missing a capability.
- Start with **Keys / Config / Models** when work fails because of setup, provider, or routing issues.
- Start with **Cron** when you want the system to keep checking or running something without you.
- Start with **System** when the backend feels unhealthy.
- Start with **Central Command / Hermes OS / Fleet Review** when you want “what is the state of the whole machine?”
- Use the many governance pages as dashboards for evidence and readiness, not as primary work surfaces.
